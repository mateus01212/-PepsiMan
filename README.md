## 🔍 Como funciona a decompilação?

O processo consiste em analisar as instruções MIPS originais e escrever uma implementação equivalente em C.

O código é compilado e comparado com a função original do executável do jogo.

O objetivo é alcançar um **match exato**, ou seja, produzir o mesmo código de máquina da função original.

Mesmo um código C que execute corretamente pode gerar instruções diferentes. Por isso, é importante investigar tipos de dados, otimizações, registradores e estruturas de controle.

## 🤖 Autopilot e Permuter

O decomp.wtf possui recursos de automação que podem auxiliar na reconstrução das funções.

**Autopilot:** automatiza tentativas de geração e compilação de código, conforme a configuração disponível.

**Permuter:** experimenta diferentes formas de escrever código C para encontrar resultados de compilação mais próximos do original.

A disponibilidade desses recursos depende da instalação e das configurações utilizadas.

Nenhuma correspondência deve ser considerada exata sem passar pelo verificador binário.

## 🤝 Regras para colaboradores

1. Não copiar bytes da ROM ou inserir assembly artificial para fabricar matches.
2. Não alterar o sistema de comparação para aceitar diferenças.
3. Respeitar o trabalho dos outros participantes.
4. Documentar descobertas e alterações relevantes.
5. Preservar a configuração de compilação definida para o projeto.
6. Confirmar os resultados antes de declarar uma função concluída.
